# 日镜账

中文名：**日镜账** · 前缀 `daysnap` · 端口 **6600 / 11600**

## 骨架

**日终余额抽取 → 周期快照落行 → 变动流水回放核对 → 断档/跳变检出 → 快照与回放差额清单**

皮：收单/结算账户的日终余额镜。去皮是 **周期快照事实 + 流水回放守恒 + 断档跳变检出**，不是银行核心 CRUD、不是日结封账锁定、不是双边齐账。

## 冒烟

```bash
docker compose up -d --build
# http://127.0.0.1:6600
# 台面 → 一键冒烟 → 周期快照有行 → 差额清单为空（或仅看最新回放批）
```

## 主链对象

| 对象 | 作用 |
| --- | --- |
| 账户册 | 参与日终抽取的账户 |
| 变动流水 | 按营业日增减额 |
| 周期快照 | 账户×营业日余额镜 |
| 回放核对 | 前日快照+当日流水 vs 当日快照 |
| 差额清单 | 不一致行 |
| 断档/跳变 | 缺前日镜、偏离阈值 |
| 旁置簿 | 未入账载荷 |
| 三日连环守恒 | 期初锚 + 三日流水净额 vs 期末快照，物化独立链证明（见下） |

## 三日连环守恒 · 链证明（口径 A）

跨三个营业日核「期初锚余额 + 三日已入账流水净额 = 期末快照」，并逐日校验链环。结论**禁止只回布尔**，`跑链`/`核证` 均返回富证据对象（链号、通过否、指纹、表行、每户节点/差额、同票、失效原因等）。

**架构口径全局只贯彻 A：以独立 `守恒证明` 表为权威。** 证明与 `链式批` 在同一事务写入（与链同成败），但证明独立落表；因此**归档/删除链式批后，仍可按链号读到证明行并动态核证**。这与口径 B（结论只嵌在链式批报告指纹里、删批即不可还原）明确可区分，并有测试断言。

- 指纹覆盖三日快照、流水、断档与内部 `链源纪元`：缺日、删快照、篡改余额、中日重抽、断档补齐/交错都会使旧指纹过期，核证 `valid=false`、顶层 `通过=false`，即使落库的 `原始通过=true` 也不得假通过。
- 跑链事务内用 `BEGIN IMMEDIATE` + 前后两次源指纹比对；与中日重抽/断档补齐交错检出指纹变化即失败闭（`交错冲突=1`）。
- 链证明与三日快照/流水/回放以批次票号互链（响应内 `同票`）。

接口（前缀 `/api`，路径参数用 ASCII `chain_id`）：

| 接口 | 说明 |
| --- | --- |
| `POST /连环守恒/跑链` | 跑三日链并物化证明（body 可给 `账户键们`+`营业日们`，或单个 `营业日`/`末日` 视作末日前推两日） |
| `GET/POST /连环守恒/核证/{chain_id}`、`GET /连环守恒/核证?链号=` | 连环守恒核证接口：链号 / 通过否 / 指纹 / 证明行 / `valid` |
| `GET /连环守恒/证明`、`GET /连环守恒/证明/{chain_id}` | 证明列表 / 按链号回看 |
| `GET/POST/DELETE /连环守恒/链批[/{chain_id}[/归档|/删除]]` | 链式批查询、归档、删除（不动证明） |
| `POST /断档补齐` | 补齐缺日并核销断档记录（抽取同事务推进源纪元） |

兼容别名：`/连环守恒核证/{chain_id}`、`/链证明/{chain_id}`、`/守恒证明/{chain_id}`、`/三日连环守恒/跑链`、`/三日连环/核证/{chain_id}` 等。前端入口：导航「⑥ 三日连环链证」（`/连环守恒`），台面一键冒烟含三日链并展示链号、可按链号核证。
